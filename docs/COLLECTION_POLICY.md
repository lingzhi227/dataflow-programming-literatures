# Collection policy

Keep bibliographic identity, reviewed version, retrieved file and redistribution permission separate.

1. Add a work only when it informs semantics, locality, scheduling, resource management, compiler design or spatial execution. Prefer the publisher, authors, institution or official project as the source.
2. Record title, authors, year, venue/status, source URL, one-sentence editorial introduction and reading depth. Do not copy abstracts into the catalogue. Abbreviated author lists must be marked.
3. Distinguish published papers, workshop reports and preprints. Preserve version identifiers and explain title or year differences. A newer code repository is not necessarily the implementation evaluated in a paper.
4. Preserve the original PDF bytes. Publish a mirror only when an explicit licence covering that exact version has been checked. Record authors, source, licence, evidence, version and SHA-256 in the manifest.
5. Publicly readable does not automatically mean redistributable. Default to source links when permission is unclear. The initial mirror set uses CC BY 4.0 or CC0; this conservative selection is not a ruling that other licences forbid every use.
6. Personal reading downloads and extracted/OCR text stay outside the public repository. Access failures remain visible; neither a failed endpoint nor a missing mirror means the paper was disproved or rejected.
7. Keep the repository guide and catalogue ahead of the update log. New log entries go first; previous entries remain.
8. Validate local links, metadata and file provenance before publication. Literature review, source inspection, successful build, SDK execution and hardware validation are separate evidence categories.

This collection contains no model weights, SDK images or experiment outputs. The research notes describe read-only work and proposed experiments.
