# Dataflow Programming Literatures

Dataflow programming describes computation through dependencies between operations and the values they exchange. Its history connects parallel-program semantics, processor architecture, signal processing and compiler design. MIMD classifies instruction and data streams; dataflow describes how dependencies govern execution; systolic algorithms specify structured movement and computation across an array. These ideas overlap, but answer different questions.

Early work by **Kahn** and **Dennis** established ways to reason about communicating processes and data-driven execution. **Synchronous dataflow** made fixed production and consumption rates useful for static scheduling. **Kung's systolic architectures** and **Hong–Kung I/O complexity** put locality and limited storage at the center of algorithm design: performance depends on how computation reuses data, not simply on how many arithmetic units are available.

Modern programming systems build on several of these concerns. **TensorFlow** and **TVM** organize and compile tensor computation; **Halide**, **Exo** and **Allo** separate algorithms from scheduling and hardware customization. **MLIR**, **DaCe** and **Calyx** offer different representations of computation, state, data movement and control. Elastic and hybrid HLS, including **Dynamatic**, **DASS** and **CRUSH**, address execution when latency, resource sharing and backpressure cannot be captured by one fixed schedule.

Spatial accelerators make these questions concrete. FPGA systolic arrays, TPU, AMD AI Engines, Tenstorrent and Cerebras expose different combinations of local memories, compute arrays and communication networks. **ARIES**, **AIR**, **Dato** and **TL** study how programs map onto these resources; **WaferLLM** and **MACH** examine wafer-scale algorithms and compilation. For a CUDA programmer, tiling and asynchronous transfers are familiar concerns. Spatial compilation additionally requires an explicit account of distributed storage, persistent state, communication order and resource reuse. A central research problem is making these decisions composable across a whole application.
